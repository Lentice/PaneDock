# PD-258 — 預先載入整個資料夾的類型圖示

Phase 8 · 目標 0.5 天

## 來源與交付

來源：使用者 2026-10-22 回報拖動捲軸、尚未放開時，檔案圖示仍可能沒有設定（PD-255 之後）。

交付一個結果：持續捲動或拖動捲軸時，可見列的圖示已是正確的類型圖示，不必等當下才查詢。

## 原因

PD-255 只替「目前可見」的列要類型圖示；拖動時每個新範圍都取代 worker 佇列，冷快取的類型（約 5 ms 一個）來不及載入，且一旦被逐檔圖示擠出快取就要重查。

## 綁定限制（引用）

- AGENTS：影像快取有數量與位元組上限；預載池設上限，逐檔圖示仍保有大部分快取。
- AGENTS：事件驅動，不新增 timer／輪詢；失敗的類型請求在同一個 viewport 內不重試。

## 具體範圍

`Pane::append_type_icon_requests`：可見列的類型之後，再請求「整個資料夾的其餘類型」。以每次最多 1024 列的切片掃描列，收集至多 96 種不同類型（`type_pool_`）；池內項目每次刷新 LRU，不會被逐檔圖示擠出。尺寸／DPI 變動（`cancel_list_icons`）時重建。

## Non-goals

不預載逐檔圖示；不改第二階段；不改 worker。

## 驗收標準

- [x] 測試：視窗外的副檔名（`far-away.png`）在只看前 10 列時就被請求，並在大量逐檔圖示進出後仍在快取。
- [x] ctest 全部通過（58/58）。
- [x] 實機模擬連續捲動 1.5 秒（每 30 ms 一次隨機跳轉）後 100 ms 截圖：所有可見列圖示與 Type 皆正確。
- [ ] 實機：按住捲軸拖動（需要使用者確認）。

## 交接區

- 未驗證：滑鼠拖動手感；超過 96 種副檔名的資料夾只預載前 96 種，其餘仍依可見列載入。
- 已知偶發：`managed_list_selection`、`managed_list_context_menu` 在整套測試中偶爾失敗、單獨重跑通過，疑似焦點時序，與本票無關，尚未追查。
